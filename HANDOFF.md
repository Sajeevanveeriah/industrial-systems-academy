# Handoff

Signal Works is a standalone personal academy with eight curriculum tracks, four simulated benches and six guided field projects. No employer material or live plant interface is included.

## Maintain the site

Facility services is available from the fry plant at `#facility` and directly from `facility-services.html`. The embedded instance has a workspace-scoped storage key and the completed example is read-only. Keep public training geometry and example endpoint records independent of operational drawings. Check the standalone and embedded controls when changing this module.

The linked software batch begins at `fries.html?mode=batch#momentum` with its own storage key. Momentum is the raw-receipt writer, APS releases the order against that receipt, the AVEVA panel drives the existing floor controller, and SAP reads or replays the existing inventory movements. Preserve the batch ID, order ID, lot, receipt ID, slot, historian samples and original movement IDs through reload, archive and replay. Earlier receipts/orders without original vendor evidence are labelled on import. The shift timestamps are simulated.

The production software lab hub links independently scoped public cases to browser exercises for Momentum, AVEVA and APS 4FACTORY. Preserve the distinction between the Dutch or Polish implementation evidence and the unverified Dooen application inventory. Publish only public references and fictional training scenarios.

The primary build begins at `fries.html?mode=build#site`. The site, installation, recipe and batch share the new greenfield workspace record. The previous build-from-rack record remains available under `mode=fitout`. Keep plot coordinates consistent across the site model, renderer and guide: rows A to D north to south and columns 1 to 6 west to east. Site acceptance derives from the current construction and routing evidence; rework invalidates handover. The project guide maps site, installation and production status to the learner's next action.

The homepage opens the French fry plant. The fry process, perspective scene, rack, installation and business ledger use local classic scripts. Preserve the manual and solved workspaces independently. The app saves each stage result under a stable batch/stage key, records recipe settings and masses, uses the compiled PLC route for transfers and holds motion across navigation or reload. Test the empty installation, solved operation and completed example against both direct local files and Cloudflare.

The 3D line takes its next stage from the learner's compiled sequence and follows a single carton identifier until booking. MES records completion once. While the ERP interface is online, the same event updates ERP inventory; when offline it remains queued for idempotent replay. The reference line has a separate browser storage key. Equipment and SAP training use public examples; the plant-specific products and configurations require separate identification.

The dashboard leads into the shared packing-line workshop in `production.html`. Its seven workstations share a single order record. The machines and controls scripts expose the simulated commissioning tests, PLC execution, operator screens and robot replay used by the line. Keep browser entry scripts compatible with direct local file access. The room renderer uses classic deferred scripts on both the dashboard and room page. A local file test must exercise the inspector and change rendered geometry before publishing.

- Edit the lesson content in `lessons.js`. Progress keys consist of a track ID and lesson index, so append lessons rather than reordering existing entries on a published track.
- The dashboard lives in `index.html`, `style.css` and `app.js`. The labs and field projects each have a separate HTML, CSS and JavaScript file.
- The source repository is [industrial-systems-academy](https://github.com/Sajeevanveeriah/industrial-systems-academy). The public target is the same-named Cloudflare Pages project in the Portfolio account. Publish only the build output. See README.md for the command.
- Before release, exercise quiz feedback and progress after reload, all four benches including failure paths, workbook note isolation and the mobile layout. After release compare hosted assets to the checked build. To roll back, redeploy a previously verified commit to the same project.

Practical evidence is recorded by the learner. A passed quiz, checked box or working simulation is not verification of a physical installation.
